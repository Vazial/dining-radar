## 2. 観点ごとの結果

### (1) ADR-0077・契約との一致 — 一致
- ADR 決定1（`aria-hidden` の線画、`currentColor`、塗りなし、色: 現在地緑/他は灰/≡は黒）→ 実装どおり。決定2（`navIcons` 追加、1.16.0→1.17.0）→ YAML の `contractVersion: '1.17.0'` と `navIcons` あり。決定3（testId・文言・並び無変更）→ 差分に testId・文言の変更なし（svg は既存要素の子）。決定4（折り返し調整）→ CSS に反映。決定5（直接編集）はADRに明記済み。
- `navIcons` の対象6箇所（burger、menu の2リンク、bar の3項目）と実装の svg 6個が一致。絵記号 U+2600–27BF／U+1F300–1FAFF の不在は、実測でも両テンプレのナビ範囲に無い。
- テスト実行: `tests/test_static_assets.py` 51件すべて通過（新規2件を含む）。全体テストは別途起動したが、監査完了までに結果を確認できていない（判断できなかったこと参照）。

### (2) 板との突き合わせ — 参照できた
- 板は参照できた（`.orca/drops/dsg-out/party2/`）。パスデータ・viewBox・線幅・丸端を逐語で比較した。
  - ≡: `M3.5 5.5h13M3.5 10h13M3.5 14.5h13`、20×20、1.9 → **一致**（S2-a-PcSelect、S2）。
  - 虫眼鏡（円 cx8 cy8 r5.4＋`M12.2 12.2L16 16`）、カレンダー（rect 3,4.2,12×11 rx2.2＋`M3 7.6h12M6 3v2.4M12 3v2.4`）→ **一致**。メニューは板 S2 で17px、下部バーは S2-a-SpSelect で20px で、実装のサイズも同じ。
  - 人（circle 9,6.3 r2.9＋肩の弧、線幅1.5）→ **一致**。
- 色: 板 S2 のメニューは「さがす」が緑（現在地）、「ランチ会」が灰。実装は現在地属性に応じて同じ配色になる。下部バーは板で現在地が緑、ほかは `#4B564E`。実装は既存のリンク色に従い（現在地 `#14614a`）、灰の値は既存 CSS 側が決める。ここは実行して色を見ていない。

### (3) 2テンプレート SVG 一致検査 — 妥当（弱点あり）
- 妥当な点: 手で同期している2コピーのうち SVG 部分の食い違いを、文字列の完全一致で確かに捕まえる。範囲の切り出しは両テンプレに実在する開始・終了の目印を使っている。`index` は目印が消えれば ValueError で落ちるため、黙って空比較にはならない。
- m-2（弱点）: 抽出が「0個 vs 0個」でも一致検査は通る。ただしテスト1が両方とも6個を要求するので、実質は塞がっている（テスト1とテスト2の組で成立）。
- m-3（弱点）: テストは「SVG が互いに同じ」しか見ない。板どおりの形（パス）は固定していない。契約も形を固定しない方針なので契約違反ではないが、両テンプレを同時に誤って変えても通る。
- 絵記号の正規表現は異体字セレクタ U+FE0F や、範囲外の絵記号（例: U+2B50）は検出しない。契約の範囲どおりなので不一致ではない。
- 色（currentColor と CSS の対応）やアイコンのサイズはテストされない。契約が「固定しない」としているため範囲外。

### (4) a11y — 問題なし
- 6個の svg すべてに `aria-hidden="true"` と `focusable="false"`。名前は隣接の文字が担う: ≡ は `visually-hidden` の「メニュー」、メニューの2リンクは本文の文字、下部バーは `primary-nav-bar-label`。絵文字のときと同じ構造で、読み上げは変わらない。
- 絵文字の `<span aria-hidden>` を svg に置換しただけで、リンク・ボタンの名前は保たれる。`aria-expanded`・`aria-controls` 等は無変更。
- 色だけで現在地を示してはいない（既存の `data-primary-nav-current` の太字等が併存）。
