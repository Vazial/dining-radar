## 指摘一覧

### Critical

### Major
- **M-1 小窓の幅が板と違う（450px。板は600px）。**
  板 N1-Pc1／Pc2 の小窓は `width: 600px`、角丸16px、足は右寄せ（`justify-content: flex-end`）。
  実装は `width: min(28.125rem, …)`＝450px（`organizer.css` の `.gathering-review-dialog`）。撮影 `after-review_dialog-pc-1440.png` の小窓は約450px（495〜945）。板の画像（`board-N1-Pc1.png`）の小窓は約600px（368〜968）で、板の方が3割ほど広い。
  450px は監査 A-4 の文面（「約450px」）に合わせた値だが、板の数値と食い違う。A-4 の記述が板を読み違えていた可能性が高い。高さは中身に合わせてあり（約385px、行3つ）、縦長の空きは直っている。
  直し方: 幅を 37.5rem（600px）にするか、450px を人間が選ぶなら板か A-4 を直す。どちらかに揃える。
- **M-2 画面の列の幅が板と違う（約894px。板は640px）。**
  板は幅640pxの1本の列（`width: 640px; align-self: center`）に名前・カレンダー・帯・つくるが入る。
  実装は白いカードの内側いっぱい（約894px、撮影 273〜1167）にカレンダーを広げた。「全幅」にはなったが列の幅は板の約1.4倍で、日付1マスが板の約91pxに対し実装は約128px。
  カレンダーが列いっぱい・帯が列幅・つくるが列幅、という並びは板どおり。幅だけが違う。
  直し方: 作成画面のカードの幅を640pxに絞る、またはこの差を意図的な差として記録する。

### Minor
- **m-1 小窓の足の並び。** 板は「カレンダーにもどる｜この N日でつくる」が中身の幅で右寄せ。実装は2つが同じ幅で小窓の全幅に伸びる（`.gathering-review-footer .gathering-btn { flex: 1 1 0 }` はスマホ用のまま）。小窓の幅を広げる（M-1）と、さらに間延びする。
- **m-2 小窓の「次の月」。** 板は「10月 ›」と月名つきの枠ボタン。実装は小さな矢印だけ（`›` 薄い灰色）。契約の testid・月送りは守られているが、見た目は板と違う。これは今回の差分の範囲外（以前からの差）。
- **m-3 見出しの「ほかの月にも N日」の帯。** 撮影の状態（10月だけ選択）では帯が出ないので、帯の並び替え（`order`、矢印の連結の `margin-left: calc(-0.5rem - 1px)`）が板どおりかは撮影からは確かめられない。判断できない。別の月にも選んだ状態の撮影を1枚足すとよい。
- **m-4 スマホの「選んだ日」の文言。** `gathering_create.js` の「N日」は幅で分けていないので、スマホ幅の固定の帯にも「10月 3日」と出る（以前は「10月 3」）。板のスマホ（N1-Sp1）の帯は「6か月」で、どちらにしても板とは別物。回帰ではなく、板に近づく向きの小さな変化。ただし「スマホは変わらない」とは言えない点を記録する。

### (2) スマホ幅（<64rem）
- 追加した CSS は全て `@media (min-width: 64rem)` の中。既存のスマホ側は `max-width: 63.999rem`（`organizer.css` 約570行）で、境界に隙間も重なりもない。
- 小窓の `display: none`（握り棒）も PC の `@media` 内で、基本の `.gathering-review-grip` は `display` を持たないので、後ろの規則に負けず、スマホでは握り棒が残る。
- JS の「N日」は幅を問わず変わる（m-4）。レイアウトは変えない。
- スマホ幅の撮影（390×844）は今回の添付に無い。CSS の読みだけで「変わっていない」と判断した。撮影での確認はしていない。

### (3) 契約の Must
- `data-testid`（`gathering-create-review-open`／`-dialog`／`-submit`／`-cancel`／`-month-previous`／`-month-next`、カレンダーの月送り、名前入力）に変更なし。差分は CSS と文言の1か所だけ。
- `review-open` の disabledState（名前なし・日なしで無効）は JS を触っていないので維持。
- 契約は「選んだ日の件数の文言は固定しない」（`review-open` の requiredOutcome）ので、「N日」は契約違反ではない。
- 月送りの順序の入れ替えは CSS の `order` だけで、DOM の順は変わらない。キーボードの順も変わらない。
