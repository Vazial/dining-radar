# ADR-0008: 再提案の表示済み候補は画面内だけで減点し、位置の推測は Want とする

> **承認者向けサマリ**: この製品では訪問履歴・ブラックリスト・店舗照合情報を保存しない。再提案は毎回 provider を新規検索し、同じ画面を開いている間に既に表示した店舗だけをブラウザ内で順位低下させる。候補は除外せず、更新・サインアウトでこの状態を破棄する。非公開の検索地点を直接出さないことは Must、候補店舗と地図から大まかな地域を推測できることの防止は Want とする。

## 文脈

候補の再提案で既に見た店舗を避けたい一方、訪問履歴やブラックリストを実装するには、provider の店舗を継続して照合する識別子と保存先が必要になる。現時点の Hot Pepper の利用条件と ADR-0002 は provider 応答・識別子の保存を現行候補検索の境界外としている。

候補店舗を地図で見せる以上、認証済みの利用者は表示された店舗から対象地域をおおまかに推測できる。これは提供価値と両立しない完全な秘匿ではなく、検索基点そのものを返さないという境界とは分けて扱う必要がある。

さらに Hot Pepper と OpenStreetMap の公開条件を守るには、クレジット、通常の対話的なタイル利用、HTTPS の provider 通信、秘密情報の非露出を実装境界として明確にする必要がある。OSM 標準タイルへ適切な Referer を送るため、公開運用時の Referrer-Policy はクロスオリジンには origin だけを送る `strict-origin-when-cross-origin` とする。

## 決定

1. この製品では訪問履歴・ブラックリスト・長期の候補照合を実装しない。provider ID、HMAC 等の provider ID 由来トークン、provider 応答、実店舗データを DB、セッション、fixture、ログ、Git に保存しない。この方針を再検討するには、新たな人の意思決定、provider 規約の再確認、新規 ADR を必要とする。
2. 再提案は毎回 fresh provider search を行う。ブラウザは同一画面のメモリだけで、以前に表示した店舗との一致を `providerPageUrl` の完全一致で判定し、今回の候補の表示順位を二次的に下げる。未表示の候補を先にし、既表示候補は除外しない。同順位内ではサーバーの決定的な順序を保つ。
3. この表示済み状態はブラウザから server へ送らず、storage、cookie、URL、ログへ書かない。ページ更新、タブを閉じる、サインアウトで破棄する。これは provider-response cache や durable history ではない。
4. 正確な検索基点・設定範囲を browser、公開 URL、ログ、エラー、trace、Git に出さないことは Must とする。一方、候補店舗・その位置・provider 詳細リンクからおおまかな地域を推測できることの防止は Want とし、現行製品では保証しない。
5. Hot Pepper は server-to-provider の HTTPS 通信だけで利用し、必要な text credit を候補表示に出す。provider 画像、スクレイピング、fallback、response cache・永続化は使わない。Leaflet は OSM 標準タイルを小規模な認証済み対話表示だけに使い、可視の帰属表示を行い、prefetch、bulk download、offline cache を行わない。公開運用では `Referrer-Policy: strict-origin-when-cross-origin` を用いる。これは URL path、query、非公開検索基点をタイル提供者へ送らず、公開 origin だけを送る。Django の same-origin session、CSRF、cookie の境界は変更しない。

## 根拠

- 長期的な店舗照合を保存しないため、provider データ保存と識別子管理の未解決な規約判断を現行製品方針へ持ち込まない。
- 表示済み候補を完全除外しないため、候補数が少ない場合にも比較可能性を失わない。
- ブラウザだけの短い表示状態なら、再提案の重複感を下げつつ、server 側に過去候補を渡さない。
- 候補店舗だけの地図はプロダクト価値であり、地域推測の完全防止より、正確な検索基点の非露出を優先する。

## 代替案

- **訪問履歴・ブラックリストを private runtime DB に保存する**: provider ID または HMAC を継続保存する規約判断が必要なため採らない。
- **以前の候補識別子を再提案リクエストへ送る**: browser-to-server の候補履歴となるため採らない。
- **既表示候補を常に除外する**: 候補不足を招くため採らない。
- **候補地図を廃止して地域推測を防ぐ**: 地図比較の合意済み価値を失うため採らない。

## 結果

- 再提案後にも以前表示した店舗が現れることはあるが、未表示候補より後ろに表示される。
- 更新・再ログイン後の候補は過去画面の表示状態を考慮しない。
- 履歴・ブラックリスト・永続照合はロードマップ項目ではない。方針を再検討する場合は、新たな人の意思決定、provider 規約の再確認、新規 ADR の人による承認を先に行う。
- 公開運用前および provider/地図利用方法を変更する前に、最新の provider と OSM の条件を再確認する。

## 既存決定との関係

ADR-0001 と ADR-0002 の利用済み・ブラックリスト、provider ID、HMAC に関する記載は、過去の設計時点における境界と未解決条件を記録したものであり、導入を要求しない。本 ADR はそれらの承認済み履歴を書き換えず、現在の製品方針として保存なしの代替を採ることを記録する。`product-brief.md` はこの方針に合わせて更新する。
