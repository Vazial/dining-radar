# ADR-0083: 撮影と描画不変条件でレスポンシブ崩れを検知する

## 文脈

KEN-69 の現行 main を指定サイズで撮影したところ、スマホのホーム行で「開く」や日時が重なり、会の店選択画面では iPad 縦長で確定バーが回答リンクを覆い、日時が生の ISO 文字列になる崩れが見つかった。従来の検査だけでは、画面に表示された内部表現や横方向のはみ出しを直接検知できなかった。

## 決定

1. 撮影の標準サイズは 375×812、820×1180、1180×820、1440×900 とし、合成データに3件以上の会、長い会名・店名、多人数、全局面を含める。
2. 撮影は `DINING_RADAR_CAPTURE_DIR` で任意の出力先に保存する。撮影画像は目視確認の証拠とし、画面の期待値を固定するゴールデン画像にはしない。
3. L5 の描画検査は、横スクロール、ISO日時、内部ID・キー・UUIDの可視化を失敗にする。既存の構造・幾何検査と組み合わせ、skip/xfail を追加して不具合を隠さない。
4. 表示日時は利用者向けのローカル表示形式に変換し、API の値をそのまま描画しない。

## 帰結

- 画面の崩れを撮影で発見し、修正後に同じサイズで再撮影できる。
- 画像の字体や地図などの環境差は、構造検査と目視で扱い、ピクセル完全一致にはしない。
- 既存の API、ブラウザ契約、`data-testid` は変更しない。
