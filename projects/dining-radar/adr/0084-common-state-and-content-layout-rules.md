# ADR-0084: 空状態・長い内容・多人数・エラーの共通表示規則

> **承認者向けサマリ**: 板がまだ無い状態ごとに別の見た目を発明すると、画面ごとの例外が増えて板と実装の照合ができなくなる。空状態、長い名前、多人数の表、エラー表示を、画面をまたいで同じ機械検査で守る。

## 文脈

KEN-70 で、店0件、候補日0件、回答0件、リンク0本、情報不足、長い名前、多人数、エラーなど、既存の板が無い状態を洗い出した。これらを状態ごとに別の板で確定すると、同じ問題（空白、はみ出し、内部値の露出）が画面ごとに再発する。店0件については案Aを採用するが、残りの状態は共通の構造規則で先に検証可能にする。

## 決定

1. **0件**: 通常状態と同じ枠・列・手順の構造を保つ。空状態の案内は1行、利用者が次に行うメインボタンは1つだけにする。
2. **長い名前**: 名前は最大2行で省略記号（`…`）を使う。親の枠や列からはみ出してはならない。
3. **多人数の表**: 表は自身の枠の中で横スクロールできる。ページ全体に横スクロールを発生させてはならない。
4. **エラー**: 利用者向けの理由を1行と、やり直しボタンを1つだけ表示する。内部値、UUID、ISO形式の日付を表示してはならない。

## 帰結

- 新しい状態の板を起こす前でも、共通の構造・内容検査と fault-injection で実装の後退を検知できる。
- 個別画面の板は、共通規則を満たす構造の具体例として追加する。共通規則から外れる場合は新しい人間の判断が必要になる。
- 名前の省略は情報量を減らし、表の横スクロールは一度に見える列数を減らす。これはページ全体の崩れを避けるための意図した代償である。
