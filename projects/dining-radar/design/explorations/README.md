# design/explorations — 探索ラフ

**ここにあるものは承認済み設計ではない。** 方向性を人間が選ぶための探索資料であり、
承認済みの画面設計とは別物である。実装・`design/reconciliation/` と食い違う場合は、**常にそちらが正**
である。（`design-preview/`（`ADR-0003` のレビュー専用receiver）は 2026-08-24 に廃止した。`adr/0028`。）

`ADR-0025`（検索基点と徒歩時間の開示、徒歩の上限を絞り込み条件として扱う）に対応する3枚だけを置いて
いる。同じ探索では会・日程調整・出欠・承認投票・履歴の画面も描いたが、それらは**まだ承認されていない
製品境界**を前提とするため、ここには含めない。

## 形式と見かた

Claude Design のキャンバス形式（1ファイル = 1アートボード）。`<x-dc>` 直下が画面のマークアップで、
テンプレート値を持たない静的HTMLである（`renderVals()` は空を返す）。単体でブラウザに開いても
おおよそ読めるが、正しい描画は Claude Design のキャンバス上で行われる。

## 由来（重要）

**これらは designer のパイプラインを通っていない。** `meta/adr/0018`・`0020`・`0021` は designer を
design integrator と定義し、UI/UXを自ら発案しないこと・外部AIの成果物を手で書き直さないこと・実行は
orchestrator に依頼することを定めている。ここにあるラフは **orchestrator が直接描いた**ものであり、
その定義に沿っていない。

したがって、**これらを「設計骨格」の承認材料として提出してはならない**。承認点①（契約と設計骨格）に
出すには、先に次のどちらかを決める必要がある。

- **(i)** このプロジェクトのモック承認プロセスADRを起こし、orchestrator直描きの探索ラフを許容する
  ことを明文化する（`meta/agents.md` は escape hatch の受け皿をプロジェクト側のADRに委ねている）
- **(ii)** designer に定義どおり描き直させる。その場合ここのラフは人間へのインプットとして扱う

**会スコープのキャンバス群（F・A・B・B-2）については案(ii)で決着した（2026-08-29、人間裁定。
`adr/0034` 決定5）。** designer が正規経路で描き直し、ラフは人間へのインプットとして扱う。
orchestrator直描きの探索ラフを一般に承認材料として許容するかどうか（案(i)を一般方針にするか）は、
`adr/0034` が明示的に対象外としたため未決のまま残る。

先行する探索として issue #104 に4枚のラフ（案A 幹事ダッシュボード／案B スマホ一問一答／案C 候補ボード
／地図）があったが、同じ由来の問題を持ち、探索キャンバス8枚にほぼ吸収済みのため 2026-08-29 に
クローズした。本ディレクトリには取り込んでいない。

## ADR-0002 への対応

店名・徒歩分数・座標・地図はすべて**合成値**である。実在の店舗データ・provider由来の値・実在の地名・
座標・既定探索距離を含まない。provider画像は使わない（`ADR-0002` 決定5）。店舗を並べる画面には
providerクレジットの表示枠を置いているが、確定した文言は実装済み画面が持つものが正である。
